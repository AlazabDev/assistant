# دليل الربط والتكامل الشامل | Azab Assistant & UberFix & Azab Payments

يرسم هذا الدليل خريطة الطريق التقنية لتكامل تطبيق **مساعد العزاب (Azab Assistant)** مع تطبيق **إدارة المدفوعات (Azab Payments)** ونظام إدارة الصيانة والتشغيل **(UberFix)** باستخدام قاعدة بيانات سحابية موحدة على **Supabase**.

---

## 1. بنية النظام الكلية (System Architecture)

يعمل تطبيق **مساعد العزاب** كبوابة تشغيلية (Operational Gateway) على مستوى نظام الأندرويد لالتقاط المدفوعات الواردة (Inbound Payments) وإرسال إشعارات ورموز تحقق الصيانة الصادرة (Outbound SMS Tasks):

```
┌────────────────────────────────────────┐
│             سيرفر UberFix             │
└──────┬──────────────────────────▲──────┘
       │                          │
(1) إنشاء مهمة SMS          (4) إرسال تقرير بالحالة
       │                          │
┌──────▼──────────────────────────┴──────┐
│           Azab Assistant               │ <───> [ Supabase DB ]
└──────┬──────────────────────────▲──────┘
       │                          │
(2) إرسال SMS (الشبكة)       (3) استقبال تأكيد الدفع
       │                          │
┌──────▼──────────────────────────┴──────┐
│     العملاء والفنيون (أجهزة المستقبِل)  │
└────────────────────────────────────────┘
```

---

## 2. التكامل باستخدام قاعدة بيانات Supabase سحابياً

تم توفير ربط مباشر وآمن في تطبيق المساعد لإرسال وتحديث السجلات مباشرة في جداول **Supabase** عبر الـ REST API الافتراضي.

### هيكل الجداول المقترحة (Database Schemas)

#### جدول الأحداث الملتقطة `captured_events`
هذا الجدول لتخزين تأكيدات الدفع اللحظية الملتقطة من إشعارات الأجهزة (Vodafone Cash / InstaPay / Fawry ... إلخ):

```sql
create table captured_events (
    id bigint generated by default as identity primary key,
    provider text not null,               -- فودافون كاش، انستاباي، إلخ
    channel text not null,                -- sms, notification
    direction text not null default 'incoming',
    raw_text text not null,               -- نص الرسالة كاملاً
    sender text not null,                 -- رقم المرسل أو اسم التطبيق الشاحن
    received_at_device timestamp with time zone not null,
    is_synced boolean default true,
    classification text not null,         -- STRONG_PROOF, SUPPORTING_PROOF
    entity_id text,                       -- رقم المعاملة أو كود العملية (Reference ID)
    created_at timestamp with time zone default timezone('utc'::text, now()) not null
);
```

#### جدول مهام الرسائل الصادرة `sms_tasks`
هذا الجدول لسحب المهام وإرجاع التقارير الخاصة بالرسائل القصيرة الموجهة للعملاء والمهندسين:

```sql
create table sms_tasks (
    task_id text primary key,             -- معرف المهمة الفريد من سيرفر UberFix
    phone_number text not null,           -- رقم جوال الفني أو العميل المستلم
    message_text text not null,           -- محتوى الرسالة (كود التحقق OTP أو إشعار صيانة)
    status text not null default 'PENDING', -- PENDING, SENT, DELIVERED, FAILED
    retry_count int default 0,
    created_at timestamp with time zone default timezone('utc'::text, now()) not null,
    last_attempt_at timestamp with time zone,
    error_message text
);
```

## 3. آليات عمل البوابة (Operational Logic)

### أ) سحب مهام الـ SMS (Polling Worker)
* يقوم المساعد بعملية Polling دورية (من خلال `SmsGatewayService` الذي يعمل بالخلفية كخدمة Foreground فائقة الأولوية).
* تسحب الخدمة المهام عبر نقطة النهاية (Endpoint) أو بالاستعلام المباشر من جدول `sms_tasks` في Supabase حيث `status = 'PENDING'`.
* يقوم التطبيق محلياً بتسجيلها في جدول Room لمنع التكرار (Deduplication).

### ب) الإرسال الفعلي والتحديث (Device Gateway)
* يُرسل المساعد الرسائل من شريحة الشركة (SIM) محلياً.
* يُحدث حالة السجل في Supabase فوراً إلى `SENT` أو `FAILED` (مع تسجيل سبب الفشل مثل نفاذ الرصيد أو مشاكل الشبكة).
* يدعم التطبيق **سياسة حدود الاستهلاك** (Daily & Monthly Limits) لحماية شريحة الشركة من الحظر.

### ج) مقاومة انقطاع الإنترنت والتشغيل الذاتي (Robustness)
* التطبيق يضم `BootReceiver` لإعادة تفعيل الخدمة تلقائياً بمجرد إقلاع الجوال.
* يضم التطبيق صفحة إعدادات متكاملة لإدارة مفاتيح Supabase وعناوين URL وحدود الإرسال اليومية والشهرية يدوياً في أي وقت.

## 4. إعدادات التكامل على السيرفر (UberFix Server Integration)

عند رغبتك في إرسال رسالة من السيرفر، ما عليك سوى كتابة كود مشابه للتالي لإدخال المهمة في Supabase:

```javascript
// مثال كود Node.js / Server-side لإرسال مهمة SMS عبر Supabase
import { createClient } from '@supabase/supabase-js'

const supabase = createClient('https://bxuhcbfdoaflsgbxiqei.supabase.co', 'YOUR_ANON_OR_SERVICE_KEY')

async function sendMaintenanceSms(taskId, phone, message) {
  const { data, error } = await supabase
    .from('sms_tasks')
    .insert([
      { 
        task_id: taskId, 
        phone_number: phone, 
        message_text: message, 
        status: 'PENDING' 
      }
    ]);
    
  if (error) console.error('Error creating SMS task:', error);
  else console.log('SMS Task queued successfully on Supabase!');
}
```

## 5. أكواد نسخ لدمجها في تطبيق المدفوعات (com.alazab.payments)

لربط تطبيق **Azab Payments** مع **Azab Assistant** لاستقبال أحداث الدفع الملتقطة مباشرة، يمكن للمدير أو السيرفر قراءة الأحداث فوراً من Supabase:

```javascript
// الاشتراك الفوري في أحداث الدفع الملتقطة لحظياً (Real-time Payment Capturing)
import { createClient } from '@supabase/supabase-js'

const supabase = createClient('https://bxuhcbfdoaflsgbxiqei.supabase.co', 'YOUR_ANON_OR_SERVICE_KEY')

const paymentSubscription = supabase
  .channel('public:captured_events')
  .on('postgres_changes', { event: 'INSERT', schema: 'public', table: 'captured_events' }, payload => {
    console.log('تم استقبال حدث دفع جديد من تطبيق المساعد!', payload.new);
    // تفعيل أتمتة طلب الصيانة المرتبط
    const referenceId = payload.new.entity_id;
    const classification = payload.new.classification;
    if (classification === 'STRONG_PROOF') {
       console.log(`تأكيد فوري وتلقائي للمعاملة رقم: ${referenceId}`);
    }
  })
  .subscribe()
```

تم توفير وتأمين كافة مخرجات وبنيات الكود البرمجي في الأندرويد ليعمل بتكاملية 100% وبأقصى درجات الاستقرار المالي والتقني.
